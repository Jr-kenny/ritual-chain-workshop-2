The hardest step was getting the contract to run locally at all while Ritual Chain was down. The starter `RitualPredict` constructor calls `IScheduler(0x56e776BAE2DD60664b69Bd5F865F1180ffB7D58B).approveScheduler(...)` which reverts on Hardhat because that system contract has no code locally — every `viem.deployContract` and test failed with `function call to a non-contract account`. I fixed it by making the constructor tolerant with a low-level call `SCHEDULER.call(abi.encodeWithSelector(...))` and ignoring failure when code.length == 0, then added `__mock` helpers and local mocks for the HTTP `0x0801` + jq `0x0803` and `TEEServiceRegistry 0x9644` precompiles. After that I built the BTC-adjusted payout extension, which scales winnings as `base * btcPriceAtResolve / btcPriceAtCreation` (e.g. 100 stake → 200 base at 100k → 160 at 80k) while keeping the pull-based payout loop-free. Local EDR deploy and 3 Hardhat tests now pass.
